# 時間型動作（棒式這類「做幾秒、休幾秒」） — PRD

## 背景與目標

現在整個系統假設一組＝**重量 × 次數**：`sets` 只有 `weight_kg` 與 `reps`，統計吃的是「噸位 = Σ 重量 × 次數」。

棒式、死蟲、農夫走路這類動作不是這樣——它們是**做 N 秒**，然後休息。硬塞進現有模型只有兩條爛路：把秒數填進 reps（60 次棒式？），或每次都記 0 kg × 1 次（等於沒記）。

目標：讓時間型動作被**如實記錄**，而且不汙染既有的統計語意。

> ⚠ **這是本專案目前為止動到最底層的一條**。它改資料模型，而資料模型的錯誤會沉進歷史資料裡、事後很難回頭。所以先寫 PRD、先拍板統計語意，再動工——三個決策已於 2026-07-31 拍板。

vault 對應：`projects/2026-07-健身紀錄系統/`。

## 非目標（本次不做）

- 不做「組內計時器」（按開始→數秒→自動記錄）。本次只做**記錄**：做完之後填秒數。自動計時另開條目
- 不做距離型動作（農夫走路的公尺數）——同一套擴充方式，但先只做時間
- 不做「時間型的 PR 曲線」以外的新圖表
- 不改既有次數型動作的任何行為與顯示

## 名詞定義

- **次數型動作**（reps）：現況所有動作。一組＝重量 × 次數
- **時間型動作**（time）：一組＝持續秒數（可帶負重，例如負重棒式）
- **訓練量**：目前全站用的「噸位（kg）」。時間型動作沒有這個維度——這是三個決策點的根源

## 資料模型

### 動作層

`exercises` 新增 `mode`：`'reps'`（預設）／`'time'`。既有資料全部視為 `'reps'`，不需要 migration 補值以外的處理。

自訂動作（F10）建立時要能選 mode。

### 組層

`sets` 新增 `duration_seconds`（nullable, int）。

- 次數型：`reps` 有值、`duration_seconds` 為 null（現況不變）
- 時間型：`duration_seconds` 有值、`reps` 為 null；`weight_kg` 仍可有值（負重棒式），無負重時為 0

**不重用 `reps` 欄位裝秒數。** 省一個欄位換來的是：所有既有查詢、MCP、統計都得先判斷「這個 reps 到底是次數還是秒數」，那是把成本攤到每一個讀取點。

## 已定的三個決策（2026-07-31 Ryan 拍板）

### 決策一：時間型動作**不進**噸位統計

噸位的意義是「舉起了多少重量」。把時間折進去（不論用什麼係數）都會讓未來看到的每一個噸位數字失去可信度，所以不折。

時間型動作改由**總秒數**表達份量，與噸位**並列不相加**。首頁、上次訓練摘要、動作詳情頁在有時間型資料時要能同時講兩個數字，各自說得清自己是什麼。

被否決的做法（留著避免日後重提）：折算成噸位（係數是憑空捏的）、只算負重的那些（同一動作有沒有負重就進不進統計，規則難以理解）。

### 決策二：日曆熱力圖改吃**組數**

這是決策一的直接後果——不進噸位的話，一場只做棒式的訓練噸位是 0，**那天在日曆上會顯示成沒練**，等於資料在最顯眼的地方消失。

熱力圖回答的問題本來就是「這天練了沒、練多少」，組數對兩種動作都成立，改動也最小。原本的噸位分級門檻要重新訂（見 R3）。

### 決策三：時間型的 PR 是**兩張卡**

「最長單組秒數」與「單次訓練總秒數」，就這兩個。

Ryan 明確砍掉了原提案的第三張「累計次數」——那是次數而不是表現，放在 PR 卡裡沒有「破紀錄」的意義。

估計 1RM 那格**整格不出現**（不是顯示 `—`）。F86 ② 訂的三張卡橫排在時間型動作上改為兩張，版面等分。

## 需求與驗收標準

### 後端

- R1：`exercises` 有 `mode`，`sets` 有 `duration_seconds`；migration 對既有資料不造成任何行為改變
- R2：寫入時驗證兩種模式的欄位組合互斥（時間型帶 reps、次數型帶 duration_seconds 一律 422）
- R3：統計端點依決策一與決策二調整；MCP 的查詢工具要能回答「棒式我做過幾秒」

### 前端

- R4：logger 依動作 mode 換輸入（時間型：秒數輸入 ＋ 負重，沿用 F102 的直接輸入）
- R5：組列表、日曆明細、動作詳情頁的顯示依 mode 分流（`60 秒` 而不是 `60 次`）
- R6：自訂動作建立時可選 mode

### 不回歸

既有次數型動作的記錄、統計、顯示、MCP 全部行為不變——這條要有明確的回歸驗證，因為改的是共用資料層。
