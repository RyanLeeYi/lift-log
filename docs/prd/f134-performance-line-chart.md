# 動作表現頁：可點選的折線圖 — PRD

## 背景與目標

Ryan 實際使用後的回報：動作表現頁現在的「每次最佳組」長條圖看不出趨勢，**折線圖比較容易理解**；而且想知道某根對應哪一天時，得往下滑到歷史清單去對照日期，太費事。

目標：把長條圖換成折線圖，**點折線上的資料點就當場顯示那次的日期、組數與最佳組**，不必離開圖表區。

## 非目標（本次不做）

- 不改 y 值的定義——仍是「每次訓練最佳組的重量（kg）」，跟現在長條圖同一個值（Ryan 2026-08-07 選定）
- 不改資料來源與 API：`GET /api/exercises/{id}/history` 不動，不新增 endpoint、不改 response 形狀
- 不引入圖表庫（專案硬約束），不引入任何新前端依賴
- 不動區間藥丸（F119／F120／F121／F86 ④ 的檔位邏輯與灰掉可點行為）
- 不動 PR 卡（`prCards()`）與 `bestSet()`／`sessionTonnage()` 的既有定義
- 不做多動作疊圖、不做縮放與拖曳平移、不做匯出圖片
- 不動後端、不動 `app/models.py`、不碰 MCP

## 需求與驗收標準

### R1：作為使用者，我想用折線看出這個動作的趨勢，以便一眼判斷自己有沒有在進步（F134）

- Given 區間內有 N ≥ 2 次紀錄
- When 進入動作表現頁
- Then 圖表區出現一條折線，**N 個資料點**依日期由左（舊）到右（新）排列，相鄰點以線段相連；y 值＝該次最佳組重量
- Then y 軸範圍由區間內最小值到最大值決定，**最大值那點不得貼齊上緣被裁切**（點的半徑完整可見）
- Then PR 那幾次（累進最佳，沿用現行 `running` 判定）在對應資料點上有可辨識標記（沿用獎盃 icon），非 PR 的點沒有
- Then 圖表右上角仍顯示區間最大值（現行 `.bars-max` 的資訊不得消失）
- Then 圖表下緣仍顯示首末月份（現行 `.bars-foot` 的資訊不得消失）
- Then 整張圖以 SVG 或 CSS 自繪，`package.json` 的依賴數量不變

### R2：作為使用者，我想點資料點看那次的細節，以便不用往下滑對照日期（F134）

- Given 圖表已顯示 N ≥ 1 個資料點
- When 點（觸控 tap）第 k 個資料點
- Then 該點旁出現浮動資訊，**三項齊全**：日期（`M/D`）、該次組數（`n 組`）、最佳組（`{weight}kg × {reps}`）
- Then 被選中的點有視覺區別（放大或換色），其他點不變
- Then 浮動資訊的內容必須與歷史清單裡同一天那張卡一致（同一份 `sessions` 資料，不重新查詢）
- Then 點另一個資料點 → 浮動資訊換成那一點的內容（不累積出第二個框）
- Then 再點同一個已選中的點 → 浮動資訊關閉、選中狀態清除
- Then 點圖表區的空白處 → 浮動資訊關閉
- Then 切換區間藥丸 → 浮動資訊與選中狀態清除（不得殘留上一個區間的點）
- Then **命中判定用「x 軸距離最近的點」**，不要求手指精準落在點上：圖表區任一處的 tap 都會選中該 x 座標最近的那個資料點
- Then 觸控命中區在最窄裝置（320px 寬）上，每個點的可命中寬度 ≥ 44px 或 ≥ 圖寬÷N（取較小者），且相鄰命中區不重疊
- Then 浮動資訊不得被圖表容器裁切：最左與最右的點被選中時，框整段仍在畫面內（靠左／靠右對齊或位移）

### R3：作為使用者，我想預設只看到圖，需要時才展開完整紀錄，以便畫面清爽（F135）

> ⚠ 這條與 F86 ⑥ 的既有結論方向相反（F86 ⑥ 拿掉了月份摺疊，理由是「摺疊讓『最近練得如何』要多點兩下才看得到」）。Ryan 2026-08-07 明確要求清單預設收起——**若簽核通過，等於改判 F86 ⑥ 的部分結論，需在 feature_list 記錄取代關係**。

- Given 區間內有 N ≥ 1 次紀錄
- When 進入動作表現頁
- Then 歷史清單預設收起，該位置只顯示一個可點的觸發列，文字含紀錄次數（例「查看完整紀錄（12 次）」）
- Then 觸發列的可點高度 ≥ 44px
- When 點該觸發列
- Then 清單展開，卡片內容與現行完全相同（`.hist-card` 的日期／相對時間／總量／組 chips／最佳組獎盃全部不變）
- When 再點觸發列
- Then 清單收回
- Then 展開／收起狀態**不跨頁面保存**：離開動作表現頁再回來，回到預設收起
- Then 切換區間藥丸時，維持使用者當下的展開／收起狀態（不因重繪而彈回收起）

## 介面契約

不新增 API。前端資料結構沿用 `GET /api/exercises/{id}/history` 現有回傳：

```jsonc
{
  "first_session_date": "2026-05-02",
  "prs": { "top_est_1rm": 92.5, "top_session_volume": 2400, "...": "..." },
  "sessions": [                       // 舊 → 新
    {
      "date": "2026-07-20",
      "sets": [ { "weight_kg": 60, "reps": 8, "rpe": 8, "...": "..." } ]
    }
  ]
}
```

圖表所需欄位全部由既有資料推出，**不新增任何欄位**：

| 圖表元素 | 來源 |
|---|---|
| 資料點 y 值 | `bestSet(session).weight_kg`（現行函式，不改） |
| 資料點 x 序 | `sessions` 的既有順序（舊 → 新） |
| 浮動資訊「日期」 | `session.date` |
| 浮動資訊「n 組」 | `session.sets.length` |
| 浮動資訊「最佳組」 | `bestSet(session)` 的 `weight_kg` × `reps` |
| PR 標記 | 現行 `running` 累進判定，邏輯不改 |

## 具體範例（輸入 → 輸出）

**範例 1｜一般情況**

輸入 `sessions`（舊→新）：`[{7/06, best 65×8, 3 組}, {7/13, best 70×6, 4 組}, {7/20, best 60×8, 4 組}]`

輸出：三個點，y 依序 65 / 70 / 60；第 1、2 點有 PR 標記（累進突破），第 3 點沒有；`.bars-max` 顯示 `70 kg`。點第 3 點 → 浮動資訊「7/20 · 4 組 / 最佳 60kg × 8」。

**範例 2｜點了再點別的**

接範例 1，選中第 3 點後點第 1 點 → 畫面上只有一個浮動框，內容為「7/06 · 3 組 / 最佳 65kg × 8」；第 3 點回復未選中樣式。

**範例 3｜單一次紀錄**

輸入 `sessions`：`[{7/20, best 60×8, 4 組}]`

輸出：一個資料點、**沒有線段**（一點連不成線），`.bars-max` 顯示 `60 kg`；點該點（或圖上任一處）→ 浮動資訊正常顯示。

## 邊界情況與錯誤行為

| 情況 | 行為 |
|---|---|
| 區間內 0 筆 | 沿用現行文字「這個區間內沒有紀錄」；不畫圖、不畫軸、無可點區域 |
| 區間內 1 筆 | 畫點不畫線（範例 3）；點擊照常可用 |
| 所有點 y 值相同（例全部 60kg） | 折線水平；y 軸不得除以 0，所有點畫在圖高中線（或固定基線），點仍可點 |
| 同一天兩次訓練 | 沿用 `sessions` 既有的分筆方式，不合併——一筆一點，x 軸不因日期相同而重疊到同一像素（照序位均分） |
| 點數很多（例 50 次） | 點半徑不放大、不省略資料點；命中靠「x 最近」不靠精準落點；不做橫向捲動 |
| `weight_kg` 為 null 或 0 | 現行 `bestSet()` 的行為不變；若該次算不出最佳組，該點跳過（不畫）且不列入折線，其餘點照常相連 |
| 浮動資訊開著時切換區間 | 關閉浮動資訊、清除選中（見 R2） |
| 鍵盤／滑鼠（桌機瀏覽器） | 點擊行為與觸控一致即可；不要求 hover 預覽，不要求鍵盤逐點導覽 |

## 技術約束（本專案特有）

- **不引入圖表庫**（`CLAUDE.md`：前端不引入框架與圖表庫）。折線用 inline SVG（`polyline` + `circle`）或 CSS 自繪，`app/static/js/` 內自行實作
- 改的是 `app/static/js/exercise-detail.js` 的 `barChart()`（及 `app/static/css/app.css` 對應樣式）。**不動同檔的 `bestSet()`、`prCards()`、`sessionCard()` 的資料邏輯**
- 動到 `app/static/` → **必須同步升版號**（`app/static/js/state.js` 的 `APP_VERSION` 與 `app/static/sw.js` 的 `CACHE_NAME`），否則 Service Worker 會繼續餵舊 JS；並出一顆 APK
- 觸控目標沿用 F113 的規則：可點元素在最窄支援寬度（320px）下不得小於 44px
- E2E 用 Playwright，一律 `uv run python tests/e2e/verify_f134.py`（不要 `uv run --with playwright`）
