# 動作詳情頁（Exercise Detail）— PRD

## 背景與目標

現在要看「某個動作我練得怎樣」只能在日曆一天天翻，看不到單一動作的長期表現與歷史。做一個**每個動作的專屬詳情頁**，一頁同時回答三個問題：

1. **看進步**（曲線）：這個動作的關鍵數字隨時間有沒有變強
2. **看紀錄**（歷來清單）：這個動作歷來每次做了什麼
3. **看 PR**（個人紀錄）：史上最好的一組

三者吃同一份資料（該動作歷來所有的組），只是三種投影。沿用 lift-log 既有的橡膠黑×琥珀 LED 語言與客戶端手繪 SVG（同 body.js），不引圖表庫、不引框架。

vault 對應：`projects/2026-07-健身紀錄系統/`（收官後補 DEVLOG）。

## 非目標（本次不做）

- 不做「預估 1RM」指標（brainstorm 中評估後 Ryan 決定砍掉，只留最重重量與最重總訓練量）
- 不做跨動作比較、不做動作間排名
- 不做匯出、分享、報表
- 不做曲線上的觸控 tooltip／拖曳選點（點是視覺參考，數值看 cap 的當前值即可）
- 不做自訂時間區間（只給固定檔位 1M~3Y）
- 不改既有 `get_progress`／MCP（那是文字查詢用；本頁走新端點）

## 名詞定義

- **最重重量**：一次訓練中，該動作所有組裡 `weight_kg` 的最大值（不乘次數）
- **最重總訓練量**：一次訓練中，該動作所有組裡 `weight_kg × reps` 的最大值（以**單組**為單位取最大，非整場加總）
- **時間窗**：`1M / 3M / 6M / 9M / 1Y / 2Y / 3Y`，預設 3M；同時控制曲線與歷來清單

## 需求與驗收標準

### 後端

#### R1：作為前端，我想用一個端點拿到某動作在時間窗內每次訓練的全部組，以便算指標與畫清單

- Given 服務已啟動且帶正確 Bearer token
- When `GET /api/exercises/{id}/history?months=N`（N ∈ {1,3,6,9,12,24,36}）
- Then 回 `200` 與 `{ prs, sessions }`：
  - `sessions`＝依日期升冪的陣列，每筆＝一次訓練：`{ workout_id, date, sets: [{ id, set_number, weight_kg, reps, rpe }] }`；只含 `deleted_at IS NULL` 的組；只含日期 ≥（今天 − N 個月）的訓練
  - `prs`＝**全期**（不受 N 影響）個人紀錄：`{ top_weight: { weight_kg, reps } | null, top_set_volume: { weight_kg, reps } | null }`（該動作全期單組最大 `weight_kg`、與全期單組最大 `weight_kg × reps`；無資料為 null）
- Given 動作 id 不存在
- When 呼叫該端點
- Then 回 `404`
- Given 動作存在但區間內無資料
- When 呼叫該端點
- Then 回 `200`，`sessions` 為空陣列（不是 404）；`prs` 仍反映全期（區間外若有資料，PR 照樣有值）

### 前端 — 曲線（View 2）

#### R2：作為使用者，我想切兩個指標看曲線，以便分別看「扛得多重」和「單組做得多」

- Given 進入某動作詳情頁
- When 頁面載入
- Then 上方有 segmented toggle 兩個選項：`最重重量`（預設選中）／`最重總訓練量`；選中者琥珀填色（btn-primary），另一個為安靜態
- When 點另一個指標
- Then 曲線就地重畫為該指標；cap 左側標籤與右側「當前值＋單位（kg）」同步更新；不觸發整頁重繪、不打新 API（同區間資料已在手）

#### R3：作為使用者，我想選時間窗，以便看不同長度的趨勢

- Given 詳情頁
- When 點時間窗檔位（`1M/3M/6M/9M/1Y/2Y/3Y`）
- Then 該檔位琥珀高亮；曲線與**歷來清單同時**重畫為該區間；預設檔位為 `3M`
- Then 切換時間窗會依該區間重新取資料（`?months=N`）

#### R4：作為使用者，我想讓折點在長區間自動變疏，以便線不糊成一團

- Given 選定時間窗，其內訓練次數為 n
- When 畫曲線
- Then 若 n ≤ 16，一次訓練一個折點（顆粒＝「每次訓練」）
- Then 若 n > 16，聚合到**每週最佳**（週桶數 ≤ 16 時）否則**每月最佳**（桶內取該指標最大值為折點）
- Then cap 顯示當前顆粒與折點數（如「每週最佳 · 12 點」）
- Then 曲線最新點與該區間最大值點加粗標示；y 軸 3 條淡格線＋數值，x 軸標 3 個日期

### 前端 — PR（View 3）

#### R5：作為使用者，我想一眼看到這個動作的個人紀錄，以便知道自己的天花板

- Given 該動作有歷來資料
- When 進入詳情頁
- Then 頁面上方顯示兩個 PR 卡（琥珀 LED 面板樣式），資料取自 R1 回應的 `prs`（全期）：`最重重量`（史上單組最大 `weight_kg`，附該組次數）／`最重總訓練量`（史上單組最大 `weight_kg × reps`，附該組 `重量×次數`）
- Then PR 為**全期**（不受時間窗影響）；各掛 🏆
- Given 動作全期無任何組（`prs` 皆 null）
- Then PR 卡顯示占位（如「—」），不報錯

### 前端 — 歷來紀錄（View 1）

#### R6：作為使用者，我想看歷來每次的組，但只到我選的區間、且不佔滿版面

- Given 詳情頁、已選時間窗
- When 看歷來紀錄區
- Then 只列出**該時間窗內**的訓練（與曲線同一區間）；標題顯示「此區間 N 次」
- Then 依月份分組、月份新→舊；**最近 3 個月自動攤開**（顯示日期 → 該日各組），更早的月份收成標頭（`YYYY 年 M 月 · K 次 · 最重 W kg`），點標頭展開／收合（▸／▾）
- Then 每個訓練日顯示：日期、相對時間（今天／N 天前）、當日總噸位；其下每組 `重量×次數 @RPE`；當日**最重那組**掛 🏆
- Then 歷來紀錄容器固定高度，內容超過即**框內捲動**（同 F20/F21 慣例），不把整頁推長
- Given 時間窗內無資料
- When 看歷來紀錄區
- Then 顯示空狀態文字（如「這個區間內沒有紀錄」）

### 前端 — 進入與返回（Entry points）

#### R7：作為使用者，我想從選動作清單進某動作的詳情頁

- Given 在選動作 picker
- When 點某動作列的詳情入口（icon，如 📈）
- Then 進入該動作詳情頁；點入口不會誤觸「選這個動作開始記錄」（兩者分離）
- When 在詳情頁點「← 返回」
- Then 回到 picker，picker 的狀態（搜尋／篩選）不被破壞

#### R8：作為使用者，我想在記錄途中查當前動作的歷史，練到一半也能看

- Given 正在 logger 記錄某動作
- When 點當前動作標頭的詳情入口
- Then 進入該動作詳情頁；**進行中的訓練狀態不遺失**（已記錄的組、離線佇列、休息計時照舊）
- When 從詳情頁返回
- Then 回到 logger 且訓練狀態完整（可續記）

### 共通

#### R9：既有行為不變、版本遞增

- Given 本 feature 只新增一頁與一個端點
- Then F1–F34 既有行為全部不變（logger 記錄／編輯／刪除、日曆、體重、課表、MCP）
- Then 改了 static 資產 → `sw.js CACHE_NAME` 與 `state.js APP_VERSION` v36→v37（兩處一起）
- Then 不新增字體/框架；深色對比可讀（互動指示符 ≥ WCAG 3:1）
- Then `uv run pytest` 綠、`uv run ruff check .` 綠；新端點有後端測試；曲線指標／自動疏密／PR／清單摺疊／兩入口有 Playwright E2E

## 技術備註

- **後端**：新增 `GET /api/exercises/{id}/history`（service 層 `history(session, exercise_id, months)`；查詢濾 `deleted_at`、依 `Workout.date` 排序；`months` 轉日期下界）。`prs` 全期 PR 另跑一次不帶日期下界的查詢（或以既有 `get_progress` 為基礎延伸），與 `sessions` 的區間查詢分開。既有 `get_progress` 不動（MCP 文字查詢用）。
- **前端**：詳情頁為 `state.js` 路由新畫面（如 `screen="exerciseDetail"`，帶 `exerciseId`）；兩個 metric 與自動疏密全部客戶端計算（區間資料在手，同 body.js 手繪 SVG）；切 metric 不重取、切時間窗才重取。
- **自動疏密門檻**：折點上限暫定 16（桶＝每週／每月最佳）；此為可調參數，實作時集中成常數。
- **返回導航**：R7/R8 需保留來源畫面狀態——picker 與 logger 各記住 return target，避免詳情頁破壞進行中的 workout（參考 F32 的 workout 狀態保存）。
