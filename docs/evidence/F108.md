# F108 — 休息綁定發起它的動作（切到別的動作時視窗不消失、記組前要擋）

（2026-07-31，v117。verify_f108.py 20/20 ＋ 真機 SM-N9750 dev v117 逐條。）

實作：`state.restExerciseId` ＋ `restExerciseNames`（雙語都存）在休息開始時快照，
隨這輪一起持久化（F66 的 restSnapshot 加兩個欄位，舊快照缺欄位就回 null）。
`restBelongsToCurrentScreen()` 收斂三個判斷（可見性回報、休息卡、休息控制）到一處。

**兩個實作上的坑（都是自動化抓到的）**：
1. **可見性旗標的極性**：`syncRestCardVisible` 的語意是「app 內的休息卡看得到嗎」，
   true ＝ 看得到 ＝ 原生把視窗藏起來。第一版我把測試的斷言寫反了，
   差點照著錯的方向去改實作。這個旗標的名字描述的是**現象**不是**意圖**，容易讀錯。
2. **停止（halt）不是這輪結束**：第一版在 stopRestTimer 一律清掉所屬動作，
   結果 F103 ③ 的「再開始」算不出這輪屬於誰、卡片回不來，而且停止後回到所屬動作的
   計時頁視窗也不會消失。改成只有**真的結束**時才清（keepForegroundService 那條路不清），
   `restBelongsToCurrentScreen()` 也因此刻意不要求 restStartedAt 非 null。
   verify_f103 抓到，16/16 恢復。

名字為什麼用快照而不是臨時查課表：臨時加的動作（F26）不在課表裡，查不到就只能講
「另一個動作」，而 ⑤ 這個視窗的重點正是講清楚**是誰**還在休息。

自動化 verify_f108 20/20，含反面：切到別的動作要回報「卡片不可見」（回報 true 的話那一頁
既沒卡片、視窗又被藏起來，倒數整個消失）；⑤ 的取消與確認**兩條路都驗**
（只驗「有跳視窗」的話，「取消也照記」會全綠）。
