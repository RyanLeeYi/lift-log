# F162 規格變更紀錄：折線圖取代體重長條圖，會影響到哪些既有條文

2026-08-20 簽核。這份檔案存在的理由是：F162 動的不只是體重那張圖，它**讓四條已經
`passing` 的 acceptance 條文不再成立**。那些條文的原文留在 `docs/archive/features.jsonl`
不會被改動（改了就是竄改），所以「哪一條被什麼取代、為什麼」記在這裡。

F136 全部、F113 觸控門檻、F86 其餘條。

## 聚合這件事，過去被否決過三次

寫下來是因為這不是「以前沒想到」，是**明確反對過三次之後改變主意**：

1. **F56 簽核時**——`body.js` 的註解記著：「刻意不做聚合抽樣：體重是天天量的連續數列，
   取週/月最佳會抹掉短期波動，而波動正是看體重的重點（F56 簽核時已告知 Ryan）」
2. **F57 ④**——直接寫進 acceptance：「仍不做折點聚合抽樣」
3. **F134 ⑧**——動作表現那邊的同義條文：「不省略資料點」

2026-08-20 改變主意的理由，以及為什麼這次的做法不吃上面那個反對：

- **取平均，不是取最佳。** 三次反對針對的都是「取週/月**最佳**」——那確實會抹掉波動，
  因為它只保留極值中的一端。平均保住的是趨勢中心。
- **min/max 進浮動框。** 點一下看得到該區間的最低與最高，波動資訊沒有消失，只是從
  線上移到框裡。
- **只在畫不下的時候才做。** 門檻 50 來自 F135 ② 自己的保證——「320px 寬、圖寬 252px 下
  相鄰未選中點圓緣間距 >= 1px」，4px 的點需要 >= 5px 間距，252 / 5 約等於 50。
  超過這個數字那條保證本來就斷了；聚合接在它斷掉的地方，不是提早介入。
- **與「固定截斷」的差別**：體重圖原本有一個 24 筆的靜默上限（`BAR_COUNT`），選「全部」
  也只畫最後 24 筆，畫面上看不出來——F56 曾以 P3-4 接受這個降級。聚合不丟資料而且在
  標題上明示（「每週平均」），是相反方向的東西。F162 一併移除了那個靜默上限。

## 門檻 50 與既有 E2E 的關係

`verify_f134.py` ⑧(c) 的壓力情境是 **50 筆**，`verify_f135.py` 也用 N=50。聚合的觸發
條件是 **> 50**，所以那兩支腳本的斷言（「不省略資料點」「點徑 4px」）仍然成立。

這不是運氣：兩個數字來自同一個計算（252px 圖寬 ÷ 5px 最小點距）。當初挑 N=50 當壓力
情境的人，挑的正是「剛好還撐得住」的那一點。

## 整合時修掉的兩個問題

1. **`.line-tip-sets` 撞 Playwright strict mode**：抽共用模組時把浮動框的三個 class
   壓成兩個，同一個框裡出現兩個 `.line-tip-sets`，`verify_f134` 當場紅。三個名字必須
   各自唯一，已改回依序 `line-tip-date` / `line-tip-sets` / `line-tip-best`。
2. **圖表底部的日期標示被一併刪掉**：移除長條圖時 `.body-bars-foot` 跟著沒了，但那是
   **F57 ⑤ 明文要求**的區間邊界。x 軸是序位等距，沒有它「選 3 個月」與「選全部」在
   畫面上長得一樣。已改用 `.bars-foot` 補回。
