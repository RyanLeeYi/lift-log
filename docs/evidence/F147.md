# F147 — User-scoped MCP token

實作日：2026-08-14。

## 做了什麼

- `app/control_models.py`：新增 `McpToken`（uuid PK、`user_id` FK＋index、`name`、
  `token_hash`（unique）、`created_at`、`last_used_at`、`revoked_at`）。表由既有
  `ControlBase.metadata.create_all` 自動建立，無需 migration。
- `app/services/mcp_tokens.py`：`create_token`（`secrets.token_urlsafe(32)` 明文只回傳
  這一次，DB 只存 `sha256` hash）、`list_tokens`、`revoke_token`（別人的 token id 一律
  `NotFoundError`→404，已撤銷再撤銷冪等）、`resolve_token`（hash 查找＋`revoked_at is
  None`＋`user.status == "active"` 才算有效，成功更新 `last_used_at`）。
- `app/api/mcp_tokens.py`：`POST/GET/DELETE /api/mcp-tokens/`，複用
  `app/api/deps.py::require_domain_auth` 做 session 解析／CSRF／rate limit；
  `domain_scope == "legacy"`（單一共用 token 沒有 user 身分）一律 401。
- `app/mcp.py`：`create_mcp` 新增 `control_session_factory`／`settings` 參數（皆可選、
  預設 `None` 以維持既有 legacy-only 行為，既有 in-process 測試不受影響）。
  `DomainTokenVerifier` 同時接受 legacy token（`client_id="lift-log"`）與 user MCP
  token（`resolve_token` 命中則 `client_id=user.id`）。八個 tool 共用新的
  `domain_session()` context manager：legacy 沿用建 server 時傳入的共用
  `session_factory`；user token 才依 `get_access_token().client_id` 解析
  `canonical_user_db_path`，開臨時 engine，用完 `dispose()`。DB 不存在／使用者非
  active 時整段回 `{"error": "data unavailable"}`。domain 寫入全部沿用既有
  `app/services/*`（已呼叫 `projection.record_write`），MCP 層沒有新增第二條寫入路徑。
- `app/main.py`：註冊 `mcp_tokens.router`；`create_mcp(...)` 呼叫補上
  `control_session_factory` 與 `settings`。

## 為什麼這樣做（授權範圍內的判斷）

- **`domain_session()` 用 context manager + 例外，而不是回傳 `sessionmaker | None`**：
  user-scoped 請求每次都要開一顆臨時 engine 並在用完後 `dispose()`（避免長跑 server
  累積檔案控 handle），context manager 是唯一能同時處理「取得 session」與「保證
  dispose」的寫法；`_DataUnavailable` 例外讓 8 個 tool 只需加一層 `try/except`，不必
  在每個 tool body 裡插入「if factory is None」的分支判斷。
- **`control_session_factory is None` 時完全跳過 `get_access_token()`**：fastmcp 的
  in-memory `Client(mcp_server)` transport 不走 auth 層，`get_access_token()` 一律回
  `None`；既有測試（`tests/test_mcp.py`、`tests/test_daily_status.py` 的 `mcp_server`
  fixture）都是這條路徑，不能讓它們因為新邏輯而意外要求真的 access token。
- **HTTP 層真實 round-trip 測試改用 `httpx.ASGITransport` + fastmcp
  `StreamableHttpTransport(httpx_client_factory=...)`**：fastmcp 的 in-memory transport
  不觸發 `auth=` 驗證（用探針腳本證實 `get_access_token()` 恆為 `None`），要驗證「user
  token 只 route 到自己的 DB」必須真的走 `/mcp/` 的 ASGI 呼叫鏈；用
  `app.router.lifespan_context(app)` 手動啟動 FastMCP 的 session-manager task group
  （等同 `mcp_app.lifespan`），全程 in-process、不開真連線埠。
