## 過程中發現並修掉的兩件事

**1. uv 的 `.exe` shim 不能改名。** 第一次部署失敗並自動回退，log 只有一行
`Failed to canonicalize script path`。在隔離環境重現確認：uv 把 venv 的絕對路徑
寫死在 `.exe` trampoline 裡，`.venv-staging` 改名成 `.venv` 就壞。改用
`python.exe -m uvicorn`（靠 `pyvenv.cfg` 與自身位置解析，不受改名影響）。

這個缺陷只有真的跑一次部署才會現形——靜態讀 `deploy.ps1` 看不出來。

**2. 備份會靜默備到錯誤的 DB（本次引入的回歸）。** `.env` 隨正式站搬走後，從 repo
目錄跑 `backup.py` 會落回預設的 `./control.db` 與 `./users`，而那兩個路徑在工作樹
底下剛好是測試站的檔案：exit 0、印出 `[OK]`，看起來完全成功。
`docs/operations.md` 補了正確跑法，但文件層緩解不夠——這支腳本的正常歸宿是排程
工作，警告沒有人會看到。所以 `backup.py` 改成**拒絕執行**：讀不到 `.env` 又沒有
明講 `--control-db` / `--user-data-dir` 時 exit 2。回歸測試見
`tests/test_backup.py`（三條：該擋的擋、明講來源可跑、有 .env 可跑）。
