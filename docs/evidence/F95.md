## 真機序列（截圖對照）

1. **前提**（`F95_01_baseline_on.png`）：app 層通知允許、`rest-timer` importance=2、`default` 正常
   → 設定頁「休息提醒」顯示**開**。
2. 記一組伏地挺身（休息 300s）→ 前景服務發出 `rest-timer` 通知（`F95_02_rest_notification.png`，
   `dumpsys notification` 亦可見 `id=2001 channel=rest-timer importance=2`）。
3. **長按該則通知**（`F95_03_longpress_panel.png`）：One UI 的面板只給「靜音傳送／關閉通知」，
   而「關閉通知」的確認框寫的是**「關閉此應用程式的通知嗎？」**（`F95_04_longpress_app_level.png`）
   ——**這台 OEM 的長按路徑是 app 層，不是 channel 層**，acceptance ⑥ 描述的
   「關閉這類通知」那顆按鈕在這支手機上不存在。已取消，改走等價的 channel 路徑（下一步）。
4. 由系統的「通知類別 → 休息倒數」把該 channel 關掉
   （`ACTION_CHANNEL_NOTIFICATION_SETTINGS`），`dumpsys` 確認
   `mId='rest-timer' ... mImportance=0`，同時 app 層仍是「顯示通知：開」、`default` 未動
   （`F95_05_channel_off.png`）。
5. **回 app**（`F95_06_toggle_off.png`）：「休息提醒」變成**關**。這正是 F95 要擋下的靜默失敗
   ——F65 只看 default 的話這裡會顯示「開」。
6. 點該開關（`F95_07_settings_landing.png`）：跳到本 app 的系統通知設定頁
   （`顯示通知` 為開，下方即「通知類別」入口）。訊息文字本身由 E2E 驗（見下方「⑤ 為什麼靠 E2E 驗文案」）。
7. **還原**（`F95_08_restored_on.png`）：把 `rest-timer` 開回 importance=2 之後，
   「休息提醒」自動變回**開**——反向也成立，不是黏住的旗標。

## ⑤ 為什麼靠 E2E 驗文案

`enableNativeNotify()` 在同一個 tick 內既 `showError(reason)` 也 `openSettings()`，
系統設定頁會**立刻蓋掉**畫面；回到 app 時 resume 重繪已把 `state.error` 清掉。
所以那行字在真機上拍不到（試過連拍與返回後回捲，都只拍到設定頁或已清空的畫面）。
文案的判定改由 E2E 承擔，斷言的是渲染出來的 `.error-banner` 內容：

```
⑤ 訊息指出是「通知類別」被單獨關掉（實際：休息提醒的通知類別被單獨關掉了——已開啟設定頁，在通知類別清單裡打開後回來再按一次）
⑤ 訊息不寫死類別名稱——講錯名字會讓人在對的頁面上找不到東西
```

## E2E 本場修的東西（F146／F149 造成的腐爛，非 F95 缺陷）

`verify_f95.py` 原本停在 `wait_for_selector("input")` 逾時：假 plugin 宣告 `isNativePlatform: () => true`，
而 F149 之後 app 版的 setup 畫面**只剩 Google 登入**，沒有 token 輸入框，腳本連設定頁都到不了。
修法三件（都在腳本內，沒有動產品程式碼的行為）：

1. 假 plugin 補上 `AuthSession` / `LocalStore` / `Sync`（形狀抄 `verify_f144.py` 既有的 native 開機 mock），
   讓「Google session → LocalStore → Sync bootstrap」這條開機路徑走得完。
2. 假 access token 改用 e2e server 的 `LIFTLOG_TOKEN`，否則每支 API 都 401。
3. `**/api/mcp-tokens/**` stub 成 `[]`：那支 endpoint 對 legacy scope **一律 401**（F147 刻意的），
   而 401 會被 `guard()` 判成登入失效把畫面踢回 setup。
   ⚠ 這條 route 必須註冊在 `reroute_public_host()` **之後**——Playwright 是後註冊的先比對。

**其餘 18 支宣告 native 的 e2e 腳本（f61–f71、f89、f103–f108 等）很可能有同一個病**，本場沒有逐一掃。

## 順帶發現（不在 F95 範圍內，已另開條目）

休息結束的那則提醒走的是**第三個 channel `rest-alarm`**（顯示名「休息時間到」，importance=4），
它**不在** `REST_CHANNEL_IDS` 裡。使用者若只關掉它，開關仍顯示「開」而歸零提醒不會出現
——與 F95 要消滅的靜默失敗完全同型。本場實機看到該通知確實掛在 `rest-alarm`
（`F95_02` 之後的畫面與 `dumpsys` 皆可見）。
