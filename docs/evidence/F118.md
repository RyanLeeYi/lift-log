# F118 — 體重補記換日期時沒帶入該日既有紀錄

（2026-08-01，v130）

## 根因

`dateInput.onchange` 查的是 `body.metrics`——**當下畫面上的清單**，而那份清單被時間窗篩過（F56）。
選到窗外的日子就 `find` 不到，於是走「該日無紀錄」那條路，把**最近一筆**的體重填進表單。
使用者以為在補記那天，按下記錄就 upsert 覆蓋掉那天的真實體重。

原本的 acceptance 猜「八成是時間窗或分頁籤把它濾掉」——時間窗那半猜對了，分頁籤無關
（`body.metrics` 不分 metric）。

## 修法（acceptance ③：來源要是「該日的紀錄」）

改成直接跟後端要那一天：`api.listBodyMetrics({ from: day, to: day })`。
三個細節：
- **先用清單裡的值樂觀填一次**，查回來再以後端為準覆寫——避免游標離開後表單空著等網路。
  兩者一致時使用者看不到任何跳動。
- **`dayReqSeq` 過期回應丟棄**（同 loadRange 的政策）：連續改日期時只採用最後一次，
  否則慢回的舊查詢會覆寫新日期的值——那正是這個 bug 的另一種版本。
- **查失敗不擋輸入**（離線也要能補記，F49 的原則），維持樂觀值。真正的防線在後端 upsert。
