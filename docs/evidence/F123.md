# F123 — app 內改用通知列（heads-up 兩顆鈕），浮動視窗只在 app 外

（2026-08-03，v134，dev APK `lift-log-dev-v134-F123.apk`，實機 RF8NB0BSEFE）

## 改了什麼

**`RestOverlay.java`**
- `shouldShow()` 塌成單一輸入：`active && !dismissed && !appForeground`。
  `restCardVisible` 與 `halted` 退出這個判斷（前者改當 heads-up 的條件，後者仍決定視窗畫成哪一態）。
- 新增 `headsUpWanted()` ＝ `appForeground && !restCardVisible`ーー正好是浮動視窗以前在 app 內
  會出現的那一格。**與 overlay 開關無關**：使用者把浮動視窗關掉時這兩個旗標照樣維護。
- `setAppForeground()` / `setRestCardVisible()` 兩處補呼叫 `RestTimerService.refreshAlarmSurface()`
  ——警示介面要在切前景／切頁的當下換手，不能等下一秒的 tick。

**`RestTimerService.java`**
- 新增 `rest-alarm` 頻道（IMPORTANCE_HIGH）與**另一則**通知 id 2003。
  ⚠ 不是把 2001 改頻道——已貼出的通知換不了頻道，而且 2001 每秒更新，同頻道會每秒彈一次。
- `refreshAlarmSurface()`：`alarming && headsUpWanted()` → 貼；否則收。重複呼叫安全。
- heads-up 掛在既有的 `stopAlarm()` 上收掉——「每一條離場路徑都要呼叫」那個紀律已經涵蓋
  停止／暫停／服務被回收三條路，跟著它走就不會漏。
- `setOnlyAlertOnce(true)`（超時每秒重貼，false 會每秒重新彈）、頻道 `setSound(null)`
  （聲音由 MediaPlayer 以 USAGE_ALARM 播，F72 ③ 不變）。

**`MainActivity.java`**
- `onNewIntent` 收 `EXTRA_BACK_TO_APP` → `focus` 導頁 → `stop` 結束這輪。

## 真機抓到一個**順序**的 bug（先驗到紅燈才修）

第一版寫的是 `stop` → `focus`，實測「停了但沒跳頁」。原因：`stopRestTimer()` 在**真的結束**
這輪時會把 `state.restExerciseId` 清成 null（只有浮動視窗那條 `keepForegroundService` 的停止才保留），
而 `focusRestExercise()` 正是靠它決定去哪一頁 → 直接 early-return。
我原本的註解把這件事寫反了。**順序改成 focus → stop 後通過。**

## 探針

- 浮動視窗：`dumpsys window windows` 裡 liftlog.dev **沒有 `/MainActivity`** 的那個 window
- heads-up：`dumpsys notification --noredact` 裡 `channel=rest-alarm`
兩者一起判，每步留截圖。

## ⑦ 已知限制的實機補充

heads-up 在這支實機上是 One UI 的**單行簡短樣式，兩顆鈕要展開才看得到**（w2 vs w5）。
`heads_up_notifications_enabled=1`，所以不是被關掉；那是系統的彈出樣式，**app 端無法覆寫**。
通知欄裡展開後「關閉 ｜ 回到 app」兩顆都在、都可按（已逐一驗過）。
另外測試期間手機處於「請勿打擾」，倒數中那則 LOW 通知在通知欄被系統壓下去——
同屬 ⑦ 的系統設定範圍，不在本條可控範圍內。

## Codex review 的 P2（已修，並重驗）

第一版在 onCreate 也接了 EXTRA_BACK_TO_APP，理由寫成「app 被回收後重建那條路」。
Codex 指出那條路**做一半更糟**：onCreate 早於前端 subscribeRestControl()，
emit 不暫存 → focus 與 stop 被丟掉，但原生那半已經停了 → 前端從 F66 快照還原出
一輪原生不存在的休息。已把 onCreate 那一行拿掉並寫明理由：
heads-up 只在前景存在，Activity 一被銷毀就自己收掉通知，這條路幾乎不可達；
殘留的一瞬按下去是「沒反應」而不是「狀態不一致」。
完整的延後派送記成 **F124（failing，未簽核）**。
