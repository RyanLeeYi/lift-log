# F125 — 背景記組改為「排入 → 回 app 寫入」，並跨行程重建保全

（2026-08-03，v135，dev APK `lift-log-dev-v135-F125.apk`，實機 RF8NB0BSEFE）

## 改了什麼

**原生**
- 新檔 `PendingLog.java`：SharedPreferences 存待記組（uuid／重量／次數／自體重／動作 id／組號）。
  同時只留一組；舊的沒清掉就**不覆蓋**、回傳舊 uuid（兩次按下不會變兩筆，也不弄丟未補送的那筆）。
- `RestOverlay.requestLog()` 依 `appForeground` 分流：背景 → `logQueued`、
  「已排入，回 app 後記錄」、**不設 3 秒逾時**；前景 → 完全維持現行行為。
- `RestTimerPlugin.emitLog(w, r, uuid)` 多帶 uuid；新增 `getPendingLog()` / `clearPendingLog()`。
- `EXTRA_EXERCISE_ID` / `EXTRA_SET_NUMBER` 一路搬到 `setDraft()`。

**前端**
- `logCurrentSet({ rpe, clientUuid })`：uuid 可由呼叫端帶入（④ 的核心）。
- `logFromOverlay` 透傳 `draft.uuid`；`onNativeRestControl` 把 `event.uuid` 帶進 draft。
- `replayPendingLog()`：啟動時**取件**補送，排在 `loadExercises()` 之後（要驗歸屬）。

## 兩個關鍵設計決定

**① 補送方向是「前端取件」，不是「原生推送」。** app 剛起來時 `notifyListeners` 一定會掉——
前端的 `subscribeRestControl()` 還沒跑（同一個坑的一般化版本記在 F124）。

**② 清除只掛在使用者明確結束的路徑上**（`ACTION_STOP` 分支），
**刻意不放 `onDestroy()`**：系統低記憶體回收服務時也會走那裡，而那正是最需要保住待記組的時刻。

## 這一輪最該記住的：**測資躲開了要測的路徑**

第一次驗「殺行程」時看起來全綠，但**根本沒走到補送**：
「app 切到背景」**不等於**「JS 被凍住」——Chromium 的 page freezing 有延遲，
剛切出去的那幾十秒 JS 還活著，bridge 事件當場就寫入並清掉了 PendingLog，
force-stop 時已經沒東西可補。截圖 `c4` 露出馬腳：按下之後圓環立刻變成**新一輪**在跑。

真正驗到補送的做法：**臨時把背景分支的 `emitLog` 拿掉**出一顆一次性 dev APK
（`lift-log-dev-v135-TEMPVERIFY.apk`），讓「JS 真的沒收到」成立，驗完再還原。
與 F118／F121 同一類教訓——**造測資時要先問「這組資料會不會讓兩種實作都通過」**。

## Codex review 的兩條（都修了，並重驗）

**[P1] 補送會把該動作既有的組從本機鏡射抹掉。**
`logCurrentSet()` 會 push 進 `state.doneSets`，接著 `rememberDoneSets()` 用它**整個覆寫**
`doneByExercise[動作 id]`。開機時 `doneSets` 是空陣列 → 那個動作先前的組會從清單與課表進度消失。
修法：補送前先把該動作既有的組 seed 進 `state.doneSets`，事後只還原 `doneSets`、
**不還原 `doneByExercise`**（那份已含補送的這一組，正是要留的結果）。

**[P2] 歸屬判準。** Codex 指出「`restExerciseId` 為 null 時反而放行」，擔心寫進**別場**訓練。
第一版照字面改成「必須等於 `restExerciseId`」→ **真機驗到補送整個不發生**（#17 沒寫入）：
使用者在視窗按過「停止」之後那輪已 halt，重開 app 時 `restExerciseId` 就是 null，
而那正是這條 feature 的主要情境。

最終修法：**判準改成 workout 身分**（`pending.workoutId === state.workoutId`），
精準命中 Codex 擔心的失敗模式；`restExerciseId` 降為附加條件（非 null 才比）。
為此把 `workoutId` 一路 plumb 到 `PendingLog`。

⚠ 這一條的教訓：**照 review 的字面改，可能修掉一個假想風險卻打死真實主路徑。**
Codex 指出的風險是真的，但它建議的判準不是最合適的那個——真機那一次紅燈才問出「該驗什麼」。

（P1 症狀不再出現）、未填累度計數 4 → 5 只 +1（不重複）。
