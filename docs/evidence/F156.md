# F156 refresh token 併發輪替不再誤判盜用

## 問題來源

使用者實機回報「手機 app 過一陣子會自己登出」（2026-08-17）。

根因不在 TTL 長度，而在**盜用偵測與併發刷新撞在一起**：

- `refresh_session` 是單次使用輪替，舊 token 被呈遞第二次即判定盜用，`_revoke_family` 吊銷整個 family。
- Android 上有**兩個互不知情的刷新者**共用同一顆 SecureStore refresh token：
  - 背景同步 `android/app/src/main/java/com/ryanleeyi/liftlog/NativeAuthSession.java:22`
  - webview JS `app/static/js/auth.js::restoreNativeSession`
- 兩者都沒有互斥鎖。開 app 時同時觸發 → 同一顆 token 被呈遞兩次 → 慢的那個被當成盜用 → 整組 session 吊銷 → 使用者被自己的背景同步登出。

網路重試造成的重送踩的是同一顆地雷。

## 修法

`app/services/auth.py` 加入 60 秒重播寬限期：

- `REFRESH_REPLAY_GRACE = timedelta(seconds=60)`
- `_within_replay_grace()`——只放行 `status == "used"`，`revoked` 不因寬限期復活
- `used_at` 只在首次使用時寫入，重播不更新，窗口無法被連續重播展延

到期、user 停用、device 不符等既有拒絕條件在 grace 判斷之後**無條件**執行，不受影響。

## 驗收（acceptance-verifier，fresh context，6/6 pass）

| # | 驗收標準 | 判定 |
|---|---|---|
| 1 | 60 秒內重播照常輪替，不吊銷 family | pass |
| 2 | 超過 60 秒後重播維持盜用偵測，吊銷 family 回 401 | pass |
| 3 | 重播不更新 `used_at`，窗口不可展延 | pass |
| 4 | 已 `revoked` 的 token 不因寬限期放行 | pass |
| 5 | idle／absolute 到期、user 停用、device 不符不受影響 | pass |
| 6 | 回歸測試覆蓋 1–4；pytest 與 ruff 全綠 | pass |

驗收者除既有測試外另寫獨立腳本走**真實兩次 HTTP 重送**覆核第 3 條（重送前後直接讀 DB，`used_at` 完全相同），以及第 5 條中「已到期但落在寬限期內」的組合（device 不符、absolute 到期、idle 到期三種皆仍回 401）。

## 未處理（另案）

- web session 固定 12 小時硬到期、無續期途徑 → **F157**
- Android 兩個刷新者的架構本身未合併（non-goal）。寬限期讓併發不再致命，但兩者仍會各自輪替，其中一顆 access token 會被對方蓋掉；Java 端有 401 → forceRefresh 的自癒路徑（`SyncHttpTransport.java:34`），JS 端的網路呼叫都先跑 `restoreNativeSession`，故影響僅止於一次多餘的往返。
