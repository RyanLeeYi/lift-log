# F100 — 浮動視窗的停止改成「停響並歸位」，不再直接消失

（2026-07-31 v112，真機驗證 SM-N9750 dev v112）
實作：RestTimerService 新增 ACTION_HALT（停鈴、停計時、歸回 targetSeconds、服務與通知繼續活著）與 halt() 靜態入口；RestOverlay 的停止鈕改送 halt、新增 setHalted() 把暫停與停止兩顆收起來、狀態字改「已停止」、F73 警示色退回一般色。
真機逐條（截圖 f100-10～f100-18）：
  ① 按停止 → 2:00（歸回這輪原設定的 120s，不是 0 也不往上數）、「已停止」、視窗留著不再倒數
  ② +15s → 2:15 且 6 秒後仍是 2:15（不重新開始倒數）；暫停與停止已收起；「回 app 記下一組」留著
  ③④ 按 ✕ → 視窗消失，且 dumpsys 查 ServiceRecord 0 筆、通知 0 筆（不留孤兒）
  ⑤ 停止期間 RestTimerService 仍在、通知在 rest-timer channel；通知文案改成「休息已停止／已停止・N:NN｜點此回 app 記下一組」，不留一則還在倒數的假通知
**真機抓到、模擬器測不到的兩個 bug**：
  1. 第一版按下停止後視窗**整個消失**——halt 送了 "stop" 事件，前端收到後走 cancelRestNotify() → stopForegroundRest() → ACTION_STOP，把服務與視窗一起關掉，剛好抵銷本條要的效果。改送獨立的 "halt" 事件，前端走新的 cancelRestNotifyScheduleOnly()（只取消排程、不動前景服務）。
  2. 收合再展開後暫停與停止兩顆**跑回來**——切換兩態會重建整棵 view，重建出來的是預設 VISIBLE，而 setHalted 只在按下停止的當下跑過一次。改在 buildExpanded 收尾時依 halted 套一次可見性。
**規格衝突已解**：③ 說「只有右上角的 ✕ 會讓視窗消失」，但那顆在 F89 ② 被訂成「右側收合圖示」、實作也是收合。它長得就是 ✕，Ryan 也是照外觀理解的；而收合本來就有另一條路（F89 ⑤ 點本體），關閉卻一直沒有入口。因此改成關閉，F89 ② 的那半句由本條取代。
⑥ 不回歸：verify_f66 22/22、verify_f65 8/8、verify_f95 9/9、verify_f89 15/15；ruff clean；pytest 274 passed。
