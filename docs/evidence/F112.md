# F112 — 就緒態可先設定這組之後的休息秒數

（2026-08-01，v121。verify_f112.py 20/20 ＋ 真機 SM-N9750 dev v121。）

實作：就緒態在 KG／REPS 下方多一列橫式步進器（`.rest-preset`），沿用 dom.js 的 `stepper()`
所以直接輸入是免費的（F102 ④）。寫入走 `setRestPreset()` → `restHintOverrides`，
與休息中按 ±15s **同一份狀態**、共用 REST_MIN_SECONDS／REST_MAX_SECONDS
（② 明訂不得另立一套）。

自動化 20/20，重點是 ⑤：**改成 90 之後記一組，圓環分母真的是 `/ 90s`**。
只驗「數字有變」的話，「畫面改了但沒寫進去」會全綠——而使用者要等到休息開始才會發現。
另有 ④ 的兩條反面（非法輸入、低於下限都不寫入）與 ⑥（休息態不顯示）。

真機（截圖 f112-01～03）：那一列顯示「休息 秒 120 −15 +15」；按 +15 後記一組，
休息卡的圓環分母是 **135s**；休息態沒有那一列。

**兩個實作坑（都是量測抓到的，不是看 code 看出來的）**：
1. ± 兩顆量到 **39px 高**（字級比 KG／REPS 小，光靠內距撐不到 F74 的 44）
   → 明寫 min-height: 44。「這是次要控制」不是放寬觸控門檻的理由。
2. `.stepper .pair` 的 base 規則有 `width: 100%`，在橫式版面裡把整列撐到超出螢幕
   （360px 上 scrollWidth 449、verify_f84 ⑩ 的水平捲動當場變紅）→ 覆寫成 `width: auto`。

版面：384×727／390×844／360×640 就緒態垂直溢出都是 **0px**
（360×640 既有的 F109 是休息態，未受本條影響）。
