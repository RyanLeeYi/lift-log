### Android instrumentation：六個範圍逐項覆蓋

新增 `android/app/src/androidTest/java/com/ryanleeyi/liftlog/F149SyncInstrumentedTest.java`（8 支）。
與 JVM（Robolectric）層的差別在執行環境——實機 Android SQLite、真實檔案系統、真實 JobScheduler。

| ⑥ 指定範圍 | instrumented 測試 |
|---|---|
| local migration | `versionOneDatabaseUpgradesOnDeviceWithoutLosingRows`（v1 → 最新版、既有列保留、重開不重跑、seed 冪等） |
| transaction rollback | `domainAndOutboxRollBackTogetherOnDeviceSqlite`、`failedMigrationRollsBackAndLeavesFileAtVersionOne`（失敗後檔案仍是 v1、寫入持續鎖定） |
| process death | `outboxAndRetryScheduleSurviveAbruptDeathAndWeeksOffline`（不 close 就丟掉 handle）＋ `retryLeavesPendingJobInRealJobScheduler`（真實 JobScheduler 留下可恢復的 job） |
| 離線數週 | 同上：21 天後同一筆 mutation 仍可送出 |
| outbox retry | `lostPushResponseRetriesSameMutationThenPullsOnDevice`（回應遺失後重送同一個 mutation_id，再 pull） |
| 兩裝置 conflict/takeover | `keepLocalRebasesOntoServerVersionOnDevice`、`useServerTakesOverAndTombstoneCannotBeResurrectedOnDevice` |

**已知天花板**（寫在測試 javadoc）：真正的 SIGKILL 無法在同一個 process 內對自己施加
（instrumentation 與 app 同 process），所以 process death 是以「不呼叫 `close()` 直接丟掉 handle」模擬，
落地與否交給實機 SQLite 自己的 journal。

實跑（實機 **SM-N9750 / Android 12**，`connectedDevDebugAndroidTest`）：

- `F149SyncInstrumentedTest` 8 tests 全綠；整個 androidTest suite **11 tests / 0 failures / 0 errors**
  （XML：`app/build/outputs/androidTest-results/connected/debug/flavors/dev/`）
- 突變驗證：把 `assertEquals(900_000, store.nextSyncAt())` 改成 `900_001`，該測試當場紅；改回即綠
- 順手刪掉 Capacitor 腳手架 `ExampleInstrumentedTest`——它斷言 `com.getcapacitor.app`，
  兩個 flavor 都不成立，跑起來只會製造假紅

**用 `dev` flavor 跑的原因**：手機上的 `com.ryanleeyi.liftlog`（prod）是 release 簽章，
debug 測試 APK 蓋不上去（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）；解法不是卸載正式版（會清掉 Ryan 的正式資料），
而是跑 `applicationIdSuffix .dev` 的 flavor，兩個 app 並存互不影響。
