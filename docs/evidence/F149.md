## ③ 識別值不得留痕 —— 2026-08-25 補實作

**先前未滿足**：Google `sub`／email 只能以 `--google-sub` / `--email` 命令列參數傳入，
會留在 shell 歷史（`ConsoleHost_history.txt`）與 process table；查無 user 的錯誤訊息還會
把識別值原樣印出來。

改法：

- 移除 `--google-sub` / `--email` 兩個 CLI flag（不是加警告——存在的參數遲早會被用）
- 識別值改由 `resolve_identifier()` 取得：環境變數 `LIFTLOG_MIGRATE_GOOGLE_SUB` /
  `LIFTLOG_MIGRATE_EMAIL`，否則走 `getpass`（不回顯）互動輸入；非互動又沒環境變數 → 中止，不 fallback
- 錯誤訊息只說「依 google_sub 查詢」，不回印識別值

釘住的回歸（`tests/test_migrate_legacy.py`，15 passed）：

| 測試 | 擋住什麼 |
|---|---|
| `test_identifier_flags_are_rejected_on_argv` | 有人把 CLI flag 加回來 |
| `test_non_interactive_without_env_aborts` | 非互動環境偷偷 fallback |
| `test_interactive_prompt_reads_sub_without_echo` | 用會回顯的 `input()` 取代 `getpass` |
| `test_error_message_never_echoes_the_identifier` | 錯誤訊息漏出識別值 |

突變驗證：把錯誤訊息改回 `google_sub={google_sub!r}`，
`test_error_message_never_echoes_the_identifier` 當場紅（實際輸出見本場 transcript）。
