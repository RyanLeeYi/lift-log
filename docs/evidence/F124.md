# F124 證據：原生→前端控制事件延後派送

2026-08-22（第十場無人看管 dispatch）。條文 ①–⑥ 見 `feature_list.json`。

## 做法（三層，缺一層就還是會掉事件）

| 情況 | 處置 | 位置 |
|---|---|---|
| plugin 在、JS 也訂閱了 | 直接送 | `RestTimerPlugin.dispatch()` |
| plugin 在、JS 還沒訂閱（Activity 重建，onCreate 早於 WebView） | Capacitor 內建 `notifyListeners(..., retainUntilConsumed=true)`，addListener 當下 FIFO 補送 | 同上 |
| plugin 不在（Activity 被回收，`instance == null`） | static bounded FIFO，`load()` 時整批重放回 retain 佇列 | `PendingRestControl` |

第二層是平台既有能力，不是自寫的：`node_modules/@capacitor/android/.../Plugin.java`
的 `notifyListeners(String, JSObject, boolean)` 在沒有 listener 時把 payload 存進
`retainedEventArguments`，`addEventListener()` 在第一個 listener 掛上後呼叫
`sendRetainedArgumentsForEvent()` 依序送出。只有第三層（instance 為 null）它救不了，
那段才自己寫。

判定在 `dispatch()` 這個唯一出口，所以涵蓋全部動作
（stop / halt / focus / plus15 / minus15 / restart / nextround / outbox / unauthorized），
不逐動作列舉。

## ④ 訂閱時機

`app/static/js/app.js`：`subscribeRestControl()` 從 module eval 當下改成
`startupRestore.then(...)`。`startupRestore` 涵蓋三條啟動路徑
（native 已登入＝`restoreNativeActiveWorkout`、native 未登入＝`Promise.resolve()`、
web＝`confirmActiveWorkout`），`guard()` 不 reject 所以 `.then()` 一定走到。
