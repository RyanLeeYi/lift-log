**review 由 Claude fresh-context subagent 執行**（Codex 額度用盡至 7/29）。findings 全處置：
・**P1-1（我的 E2E 漏掉的分支）**：切 metric 時 chips 的灰／亮不重畫、說明文字也不消失——`paint()` 只更新圖表／清單／toggle，不碰 `.body-range` 與 `.range-note`。於是體重頁籤看 3M（6M/9M 亮）切到體脂後 chips 完全不變，還留著「最早的**體重**紀錄是…」，直接打掉「分 metric 判定」的契約。修法：該分支改走 `rerender()`。**為什麼我沒測到**：④ 測的是「當前檔位不可用 → 自動退檔」（那條路徑本來就 rerender），② 只在初次載入時檢查，中間「檔位仍可用」的分支沒人測。
・**連帶挖出一個更深的 bug**：`captureBodyScroll()` 在 `render()` 開頭執行，此時 `body.metric` 已切成新的、但 DOM 還是舊 metric 的清單 → 舊清單的 scrollTop 被寫進**新 metric** 的記憶格，切回去時原本記住的位置被 0 蓋掉。先前沒發現是因為切 metric 走 `paint()` 不觸發 `render()`。修法：清單節點加 `dataset.metric`，只在相符時才記錄。
・P2-2 `rangeNote` 生命週期漏四條路徑（自訂開關／自訂套用／記錄成功／編輯刪除）→ 在 `refetchCurrent()`、自訂 chip、自訂套用三處清（自動退檔那條刻意排除，否則會清掉剛設的說明）。
・P2-3 `bounds` 只在 `openBody()` 抓一次 → 補記 2020 年的資料後，點灰掉的檔位會回「還沒有更早的資料」，與旁邊的「已補記 2020-01-01」互斥（**主動說錯話**）→ `refetchCurrent()` 內非阻塞刷新 bounds。
・P3-4 `openBody()` 固定回 3M 而不檢查可用性 → 新使用者只有幾天資料時 3M 會同時是 `on` 又 `off`（被選中的那顆是灰的）→ 改成先抓 bounds 再決定初次載入的區間（順序對調，不多花請求）。
・P3-5 自動退檔的說明改在 `loadRange` 成功後才設（失敗時別說「已改為…」）。
・P3-6 **aria-disabled 是錯的選擇**：它宣告「不可互動」，與「點了給說明」自相矛盾，而且 Playwright 會據此拒絕點擊（實測踩到）→ 改用 `aria-label`（「1Y（超出資料範圍，點擊查看說明）」）保留可互動語意。
・其他：`GET /body-metrics/range` 必須宣告在任何 `/{...}` 路由之前（加註解）、`PRESETS` 必須遞增（加註解，`longestAvailablePreset` 取最後一個）、`BodyMetricBounds.last` 前端未使用（schema 註明）。
