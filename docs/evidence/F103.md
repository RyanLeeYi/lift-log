# F103 — 浮動視窗：回 app 但倒數繼續、停止後可再開始

（2026-07-31，v115。verify_f103.py 14/14 ＋ 真機 SM-N9750 dev v115 逐條。）

實作分兩半：
  原生 — 新增 ACTION_RESTART（halted 才受理，從 remainingSeconds 重新倒數）；
        RestOverlay 多一顆「再開始」，與暫停／停止互斥，**在 buildControls 結尾統一套用可見性**
        （F100 那次的教訓：收合⇄展開會重建 view，只在按下當時設一次會被打回預設）；
        RestTimerPlugin.emit 加上帶秒數的多載。
  前端 — restartRestFromNative()／syncRestTargetFromNative() 兩個「只更新自己、不回送原生」的入口；
        syncRestCardVisible 的判斷從「REST 卡片可見」改成「人在計時頁面」。

自動化 14/14（只涵蓋前端那一半，③④ 的按鈕長相在原生、Playwright 碰不到）：
  ⑥ plus15/minus15 帶秒數 → 卡片倒數對到原生給的值（刻意用 999 這種自己走不到的值）
  ⑤ halt 不回送原生停止指令、restart 不回送原生開始指令（**兩條都是反面斷言**——
     少了它們，「照常走開始休息流程」會全綠，而那條路會讓同一輪被啟動兩次、秒數互相覆蓋）
  ⑤ restart 不帶秒數就不動作（舊版 APK：寧可不動也不要憑空猜起點）
  ② 停止之後人還在計時頁面 → 仍回報可見（舊規則在這裡不成立，視窗才會賴在 app 上面）
  ② 反面：離開計時頁面回報不可見（F69 不回歸）

真機（截圖 f103-01～13）：
  ① 按「回 app 記下一組」→ app 起來停在 logger，**倒數繼續跑**（00:58 / 119s），不是結束
  ② 停止態下按「回 app」→ 視窗消失（Ryan 回報的原始 bug）；
     在菜單頁則照常顯示收合態（F69 ① 不回歸）
  ③ 停止 → 圓環歸位 2:00、狀態字「已停止」、暫停與停止收起、「再開始」佔滿整列
  ③ −15s ×2 → 1:30；按再開始 → 從 1:30 起跑
  ④ 再開始後暫停與停止回來、「再開始」消失、狀態字回「休息中」
  ⑤ 兩邊真的同步：app 卡片的目標秒數 119 ＝ 停止前已休息的 29 秒 ＋ 再開始的 90 秒
  ⑦ 結束訓練後 RestTimerService 計數歸 0、視窗消失（F72 三條停止路徑不回歸）

回歸：verify_f69 21/21、f70 18/18、f71 27/27、f72 14/14、f73 11/11、f66 22/22。ruff clean。

⚠ **② 出過一次回歸，2026-07-31 Ryan 真機回報後修掉（v116）**：人沒離開計時頁，
第二組休息一開始浮動視窗就冒出來。成因是**狀態的所有權跑掉了**——`restCardVisible`
描述的是「人在哪個畫面」（前端擁有），卻被寫進原生 `RestOverlay.hide()` 的每輪收尾一起清成
false；前端這側 `syncRestCardVisible` 又有去重，而 ② 把條件改成單純的「人在計時頁面」之後
那個值不再變動，於是第一次送出去之後就再也不送。第二輪 `setActive` 時原生看到
restCardVisible=false → `shouldShow()` 成立 → 畫出來。

F103 之前的條件含 `restStartedAt`，每輪 true↔false 來回跳，**碰巧**每輪都把它蓋回去，
所以這個所有權問題一直被掩護著。

修法兩層都動（誰忘記都不會出事）：
  - 原生 `hide()` **不再清** restCardVisible（殘留的 true 無害：app 不在前景時
    shouldShow() 根本不看它，而 app 在前景就代表前端活著、下次 render 會送真值）
  - 前端在**開新一輪休息時強制重送**一次（`syncRestCardVisible(..., force)` 略過去重）——
    原生就是在那一刻重建 overlay，兩層的記憶必須在同一刻對齊

verify_f103 補了一條會抓到它的斷言（第二輪開始時 visible 的 true 次數必須增加），
16/16；回歸 f69 21/21、f70 18/18、f71 27/27、f72 14/14。
真機（dev v116）連跑四輪休息、全程待在計時頁，視窗都沒有出現；結束訓練後服務歸 0。

設計決定（記著）：停止再開始仍算**同一輪休息**，所以 restart 會把停止前累積的秒數接回去，
寫進下一組的 rest_seconds 涵蓋整段，而不是從再開始那一刻重算。
