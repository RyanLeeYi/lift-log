# F121 — 動作表現頁自動退檔後把紀錄濾光（「全部」檔位的起始日被算成今天）

（2026-08-01，v131）

## 症狀

動作的唯一一次訓練在 **10 天前** → 進動作表現頁，檔位自動退到「全部」，
但歷來紀錄卡 0 筆、長條圖 0 根。**那次訓練整個看不到。**

「唯一一次訓練在今天」的動作反而正常——這是它一直沒被抓到的原因，
原本的 verify_f59 測資剛好就是這一種（動作 B）。

## 根因

`exercise-detail.js` 的初次退檔自己算了一次起始日：

    const from = iso(monthsAgo(new Date(), months));

F86 ③ 加了「全部」檔位（`months === null`）之後，`longestAvailable()` 的答案就是它，
而 `getMonth() - null` 是 `getMonth() - 0` → 算出來是**今天** → `sessions.filter(x => x.date >= 今天)`
把 10 天前那筆濾掉。原本那行註解還寫著「依上述推導必為 1M」——F86 改了檔位集合，
推導失效了，註解沒跟著改。

**同一個坑 body.js 的 `datesFor` 早就註解警告過並處理了**（「不能直接丟給 monthsAgo」），
但 exercise-detail 這裡是**第二份重複的算式**，沒有跟著修。重複的算式才是 bug 的來源。

## 修法

改成呼叫本模組既有的 `datesFor({ kind: "preset", months })`——它已經處理 null
（「全部」從最早訓練日起算）。不新增第三份算式。
