# F114 — 日曆頁不產生頁面捲動：標題與「補記這一天」同時可見

（2026-08-01，v124。verify_f114.py 14/14 ＋ 真機 SM-N9750 dev v124。）

量測（384×727，Ryan 實機，**只有一個動作**的那一天）：
  修正前 docH 757 vs winH 727 → **溢出 30px**
  修正後 docH 727 → **0px**；四個動作時仍是 0px，被截斷的改成動作區塊自己捲

三個改動：
1. `detailRows()` **永遠**把動作區塊放進 `.cal-ex-scroll`（原本 >3 個才放）——
   1–3 個動作時完全不限高，明細卡直接把版面撐開。
2. `.cal-ex-scroll` 從 `max-height: 260px` 改成 `flex: 1; min-height: 0`，高度由剩餘空間決定。
   `min-height: 0` 是必要的：flex 子項預設 `min-height: auto` 會被內容撐大而不是被容器夾住。
3. `.screen.calendar` 改 `flex: none` ＋ 明確 `height: calc(100dvh - var(--app-pad-y))`。

**第 3 點是這條最花時間的地方，值得記**：畫面本來就掛了 `.fills`（F50／F52 既有的 marker），
但那個 `height` **一直沒有生效**——`.screen` 的 `flex: 1` 帶的 `flex-basis: 0%` 蓋掉了它，
項目改由內容決定大小。實測：應該是 699px 卻量到 716px，差的 17px 就是最後那段溢出。
**「有掛 .fills」不等於「拿到了確定高度」**，要量才知道。

⭐ 做到一半又進一步：第一版把 `flex: 1` 給了所有 `.cal-detail`，結果**休息日那張卡被拉滿半屏**——而那正是 F85 花力氣修掉的「空的褐色方塊」。改成只在 `cal.detail.length > 0` 時掛 `.has-sets` 才撐開。真機截圖才看得出來（f114-02）。

補記入口與批次刪除條是捲動容器的兄弟節點，所以自然留在卡片底部（③），不必另外釘住。
